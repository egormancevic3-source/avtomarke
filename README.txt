АВТОМАРКЕТ — версия с объявлениями и админ-панелью
===================================================

ВАЖНО
- Для реального хранения объявлений нужно создать бесплатный проект Supabase и выполнить setup.sql.
- До настройки Supabase сайт работает только в демо-режиме.
- Публичная форма создаёт объявления со статусом pending. На сайте видны только approved.
- Админ-панель требует вход через Supabase Auth и запись пользователя в admin_users.
- Не вставляй в index.html secret/service_role key. Нужен только publishable key (или старый anon key) с настроенным RLS.
- Из-за того, что форму может использовать любой человек, проверяй объявления и жалобы. Не публикуй документы или чувствительные данные.

ЧАСТЬ 1. Создай базу данных
1. Открой https://supabase.com/ в Safari и зарегистрируйся.
2. Создай новый проект. Сохрани пароль базы в надёжном месте; он не понадобится посетителям сайта.
3. Внутри проекта открой SQL Editor -> New query.
4. Открой файл setup.sql из этого архива, скопируй весь текст, вставь в SQL Editor и нажми Run.
5. Если SQL Editor показывает ошибку, не продолжай публикацию — скопируй текст ошибки и попроси помочь её исправить.

ЧАСТЬ 2. Создай администратора
1. В Supabase открой Authentication -> Users -> Add user / Create user.
2. Создай пользователя со своим email и сильным паролем. Если предлагается подтверждение email, подтверди его.
3. Открой созданного пользователя и скопируй его User ID (UUID).
4. Открой SQL Editor и выполни отдельный запрос, подставив свой UUID:
   insert into public.admin_users (user_id) values ('ВСТАВЬ-СЮДА-UUID');
5. Никому не передавай пароль администратора.

ЧАСТЬ 3. Подключи сайт к Supabase
1. В Supabase открой Project Settings -> API Keys (или Connect). Скопируй Project URL.
2. Скопируй Publishable key (начинается обычно с sb_publishable_). Если проект показывает старый anon key, можно использовать его.
3. В index.html найди строку:
   const CONFIG={supabaseUrl:"PASTE_SUPABASE_PROJECT_URL_HERE",supabaseKey:"PASTE_SUPABASE_PUBLISHABLE_KEY_HERE"};
4. Замени PASTE_SUPABASE_PROJECT_URL_HERE на Project URL, а PASTE_SUPABASE_PUBLISHABLE_KEY_HERE на publishable/anon key. Сохрани кавычки.
5. Никогда не вставляй secret key или service_role key в HTML. Они дают расширенный доступ и должны оставаться на сервере.

ЧАСТЬ 4. Опубликуй на Cloudflare Pages с iPhone
1. Сохрани index.html и setup.sql в приложении «Файлы». Для публикации нужен index.html; setup.sql — только для настройки базы.
2. Создай отдельную папку, например avtomarket-site, и положи в неё только index.html.
3. Открой https://dash.cloudflare.com/ и войди.
4. Workers & Pages -> Create application -> Pages -> Direct Upload / Drag and drop.
5. Назови проект, например avtomarket-bel, и загрузи ZIP с index.html или папку сайта. Если загрузчик не принимает ZIP, выбери распакованную папку.
6. Нажми Deploy site. Cloudflare выдаст адрес вида https://имя-проекта.pages.dev.
7. Открой адрес, проверь каталог и форму.

ЧАСТЬ 5. Проверка
1. Отправь тестовое объявление через форму.
2. Оно не должно появиться в каталоге до одобрения.
3. Войди в блоке «Админ-панель» под email и паролем, которые создал в Supabase.
4. В админ-панели одобри объявление, отредактируй цену/описание или удали тестовую запись.
5. Открой сайт в другом браузере и проверь, что одобренное объявление отображается.

ОГРАНИЧЕНИЯ ПЕРВОЙ ВЕРСИИ
- Редактирование цены и описания выполняется через простые диалоговые окна; остальные поля редактировать можно через Supabase Dashboard. Можно улучшить редактор позже.
- Фото загружаются в публичное хранилище, поэтому изображения доступны всем по URL. Не загружай документы, лица/номера без разрешения или другие личные данные.
- Публичная форма разрешает анонимную отправку и может привлекать спам. Модерируй каждое объявление; для большого трафика стоит добавить CAPTCHA/rate limiting через серверную функцию.
- Админ-панель скрывает функции от посетителей, но реальная защита обеспечивается политиками RLS в setup.sql. Не удаляй и не ослабляй их.
- Бесплатные тарифы могут иметь лимиты и условия, которые провайдеры вправе менять.
